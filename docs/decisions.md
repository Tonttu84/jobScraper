| D1 | The project follows the owner's shared working agreements (Tonttu84/ai-workflow) as a **solo** project: `AGENTS.md` is the rulebook, `CLAUDE.md` is `@AGENTS.md`, commits go to `main` and are pushed once `scripts/check.sh` is green. | D2 | `./scripts/setup.sh` sets up a fresh clone: `git config core.hooksPath .githooks`, then `uv sync --extra dev`. `.gitattributes` keeps `*.sh` and `.githooks/*` on LF. | D3 | The local gate before every push is `./scripts/check.sh` (ruff, the full pytest run with the browser suites, coverage at least 99 %), with the `pre-push` hook checking the outgoing commit messages. The owner's 2026-09-11 rule that data, stats and docs commits need no check is replaced by the shared rule (the gate before every push) until the owner says otherwise. Agent's reading of the shared rules during the migration. | The shared rules run the full gate before every push and the old project rule did not say it overrides them. | Keeping the exemption for data, stats and docs commits. |
| D4 | Function limits from the shared template, unchanged: Ruff C901 max-complexity 15, PLR0912 max-branches 12, PLR0913 max-args 5, PLR0915 max-statements 50, run as a report (`--exit-zero`) and not yet in `extend-select`. Measured on 2026-11-10 over `src` and `scripts` (929 functions by Lizard): these flag 35 functions (3.8 %): 4 over complexity, 4 over branches, 6 over statements, 29 over five arguments. Agent's choice during the migration. | The template values already flag only the worst few percent, so the project keeps the numbers every other project uses. Lizard's own cyclomatic count (which adds `and`/`or`) flags 62 functions over 15 and 17 over 60 lines; Ruff's McCabe count is the one the gate would use. | max-args 6 (22 functions, 2.4 %); turning the checks into errors before the flagged functions are fixed or accepted. |
| D5 | GitHub settings, approved by the owner on 2026-11-10: Dependabot alerts and security updates on; squash merges use the PR title and body; a repository ruleset `main` on the default branch blocks force pushes and deletion but requires no status check, since a solo repository pushes to `main` directly. The `commit-check` workflow runs on every push and pull request and stays visible without blocking. | `main` was unprotected on a public repository (issue #1); the shared rules give solo repositories this ruleset. | Requiring the `commit-check` status (it would reject the direct pushes of the solo flow). |
| D6 | The owner's 2026-09-11 rule is back, as an explicit project exception in `AGENTS.md` (Kind) that overrides the shared "local gate before every push" rule for these commits: data, stats and docs commits need no `./scripts/check.sh`, and a commit that only edits `config/sources.yaml` needs only `pytest tests/test_config.py`. Owner's choice, 2026-11-11. | *The full gate (browser suites, coverage) costs minutes and cannot be affected by data, stats or prose; the config test is the only one that reads `config/sources.yaml`. D3 dropped the exemption only because the old rule did not say it overrode the shared rules.* | *D3: the full gate before every push.* |
| D7 | Take the anthropic SDK major 1.4.0 → 2.6.0 (Dependabot PR #6) with no code change. v2 moves requests to API version `2026-10-21` and sends the key as `Authorization: Bearer`. Its breaking changes are `document` blocks in assistant messages, `citations` in user messages, the removed `temperature`/`top_p`/`top_k`, `MessageParam` turned into a per-role union and one credential per client; this project uses none of them. Its calls (`messages.parse` with `output_format`, `output_config` and `thinking`; Message Batches; `anthropic.APIError`) and the private `transform_schema` import were checked offline against 2.6.0 with a mock transport. Known side effect, accepted for now: 2.x honours any `Retry-After` (1.x ignored values over 60 s and fell back to a backoff of at most 8 s), so a 429 with a long `Retry-After` can hold a call for up to 4 × that value; real Anthropic values are short, and capping it is part of the open outside-call follow-up. Agent's choice, 2026-11-11, under the owner's "We can do the upkeep, dependabot etc" (2026-11-11). | Staying on 1.x would pin the project to the old API version and leave Dependabot proposing the major on every run. | Holding anthropic at 1.x with a Dependabot ignore for its semver-major. |
